# Final Project Decision Table

| # | Decision | Options Considered | Choice | Reason |
|---|---|---|---|---|
| 1 | Architecture tiers | One tier, two tiers, three tiers | Two tiers: Advisor + Weather Data | Reuses the proven Lab06 architecture, supports independent scaling, separates responsibilities, and reduces blast radius. |
| 1a | Application language | Node.js or Python | Node.js | The existing Weather and Advisor applications already use Node.js, reducing unnecessary rewriting while keeping deployment code in Python as required. |
| 2 | Weather data sources | NWS only, NWS + supplemental API | NWS + supplemental source where required | NWS is mandatory, but every required output must have a verified source. Missing fields will use a justified supplemental API rather than invented values. |
| 3 | ZIP to coordinates | Existing ZIP lookup, external geocoding | Existing ZIP lookup approach with validation | Five-digit US ZIP codes are validated before outside calls. Unknown but well-formed ZIPs receive a separate not-found response. |
| 4 | Morning and Night | Different time windows | Morning 06:00-11:59; Night 18:00-23:59 local time | Matches the suggested project definition and avoids periods crossing midnight. |
| 5 | Aggregation | Average, min/max, midpoint | Defined separately for each measured field | Different weather fields need different meaningful aggregation methods. |
| 6 | Rain/Snow categories | Model-generated or fixed thresholds | Fixed code thresholds from published sources | Categories must be deterministic, testable, and not generated by Gemini. |
| 7 | Caching | No cache, in-memory, DynamoDB | DynamoDB with TTL | Survives instance replacement, reduces repeated API calls, and matches the project architecture. |
| 8 | Gemini | Free-form output or structured output | Structured JSON advice | Easier to validate shape, types, lengths, and allowed values before display. |
| 9 | Fallback advice | Error only or rule-based fallback | Rule-based fallback | The user still receives useful advice when Gemini fails or the daily cap is reached. |
| 10 | Email service | SNS or SES | Amazon SNS | Built-in recipient confirmation provides a clear consent mechanism and keeps initial setup simpler for the class project. |
| 11 | IAM | Shared role or per-tier roles | Separate least-privilege roles | Weather cannot read Gemini secrets; Advisor receives only the permissions it requires. |
| 12 | Abuse controls | None, app limits | Per-visitor rate limits + Gemini daily cap + email limits | Protects public endpoints and limited external services from abuse. |
| 13 | Budget control | Manual tracking or automated counter | DynamoDB call counters + budget.py | Allows the project to enforce and report real usage and cost. |
| 14 | Gender handling | Free text or fixed choices | Fixed inclusive choices mapped to clothing categories | Prevents prompt injection, avoids unnecessary personal-data collection, and is used only for clothing suggestions. |
